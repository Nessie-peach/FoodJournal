# 真机测试完整流程（iPhone 安装与验收指南）

> 日期：2026-09-25 ｜ 对应版本：M1+M2+R1+R3（当前工程 8 个 commit，66 条单元测试全绿）
> 适用：免费 Apple ID 侧载（无需付费开发者账号）
> 工程位置：`something_wierd/FoodJournal/FoodJournal.xcodeproj`

---

## 一、环境准备（一次性，约 15 分钟）

### 1.1 电脑侧
1. Xcode 27 已安装（`/Applications/Xcode.app`），本机 xcode-select 当前指向命令行工具，**不影响 Xcode 图形界面使用**
   - 终端里跑 `xcodebuild` / `xcrun` 时需要先 `export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`（否则会找不到 Xcode 的工具链）
2. 打开 Xcode → 菜单 `Settings…` → `Accounts` → 左下 `+` → `Apple ID` → 登录你的 Apple ID
   - 免费账号即可，登录后 Team 显示为「Personal Team」
3. 若提示选择证书类型，选 **Apple Development**

### 1.2 iPhone 侧
1. 系统已是最新（你的 iPhone 为 iOS 27），**无需降级**
2. 打开「设置 → 隐私与安全性 → 开发者模式」→ 打开开关 → 重启手机（重启后确认启用）
   - 若看不到「开发者模式」入口：先用数据线连一次电脑再回来看
3. 用**数据线**连接电脑（首次必须线连）
4. iPhone 上弹出「要信任此电脑吗？」→ 点**信任**并输入锁屏密码

### 1.3 Xcode 工程签名配置（首次一次）

> **先解决「找不到 TARGETS」**：`TARGETS` 不在左侧文件列表里，**只有选中「工程」本身才会出现**。
> 1. 点左侧导航栏**最顶端那个蓝色图标**（名字是 `FoodJournal`；注意不是它下面那个带文件夹图标的 `FoodJournal`）；
> 2. 中间编辑器随即变成设置界面，左栏自上而下出现 `PROJECT` → `FoodJournal`，以及 `TARGETS` → `FoodJournal` / `FoodJournalTests`；
> 3. 点 `TARGETS` 下的 `FoodJournal`，右侧切到 `Signing & Capabilities` 标签。
>
> **判断走错了的方法**：若编辑器里显示的是带行号、以 `// !$*UTF8*$!` / `objectVersion = 77` 开头的源码，说明打开的是 `FoodJournal.xcodeproj/project.pbxproj`（工程文件的原始文本），**不是**工程设置界面。关掉该标签页（⌘W）后按上面第 1 步点蓝色图标即可。

1. Xcode 打开 `FoodJournal/FoodJournal.xcodeproj`
2. 左侧选中项目 → `TARGETS: FoodJournal` → `Signing & Capabilities` 标签
3. 勾选 `Automatically manage signing`，`Team` 选择你的 Personal Team
   - 本机已登录 Apple ID，Team 显示为「一铭 陶 (Personal Team)」，teamID `967ML7R2U8`
4. `Bundle Identifier` 保持默认 `com.somethingwierd.FoodJournal`；若报「已被占用 / Failed to register bundle identifier」，改成 `com.你的名字拼音.FoodJournal`（全局唯一即可）
5. 顶部设备栏选择你的 iPhone（不是模拟器）

> ✅ **本工程由 XcodeGen 生成**（`project.yml` 是唯一真身，`FoodJournal.xcodeproj` 是生成物、已被 `.gitignore` 忽略）。签名相关设置**已于 2026-09-26 写入 `project.yml`**，重新生成工程不会丢：
> ```yaml
> settings:
>   base:
>     DEVELOPMENT_TEAM: "967ML7R2U8"
>     CODE_SIGN_STYLE: Automatic
> ```
> 若以后更换 Apple ID / 换团队，改这里再跑一次 `~/.workbuddy/bin/xcodegen generate` 即可（改完记得确认 `TARGETS: FoodJournal` 的 Team 已自动带出）。

## 二、首次安装

1. 点左上角 ▶️ Run（首次编译约 1-3 分钟）
2. 手机会安装 App 并自动启动；若首次启动报错或提示不受信任：
   - iPhone「设置 → 通用 → VPN与设备管理 → 开发者 App」→ 选择你的 Apple ID → **信任**
   - 回到桌面点开「今天吃什么」
3. 若 Xcode 报 `Developer Mode disabled`：回一、1.2 确认开发者模式已开启并重启过

可选（**建议先跳过**）：无线调试需要在 Xcode 的 `Window → Devices and Simulators` 里勾选 `Connect via network`，但该入口在当前 Xcode 27 beta 里就是 **DeviceHub（正在闪退，见第五节）**，所以先别折腾无线，有线 Run 完全不受影响。设备状态可用命令行查看：`xcrun devicectl list devices`（详见 `tools/ios-devmode.sh`）。

## 五、常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 「不受信任的开发者」/ 无法验证 App | 未信任开发者证书 | 设置 → 通用 → VPN与设备管理 → 开发者 App → 信任 |
| Xcode 报 Developer Mode disabled | 开发者模式未开 | 设置 → 隐私与安全性 → 开发者模式 → 开 → 重启 |
| Failed to register bundle identifier | Bundle ID 被占用 | 改成 `com.你的名字.FoodJournal` |
| 相机黑屏 / 无反应 | 相机权限被拒 | 设置 → 今天吃什么 → 相机 → 打开 |
| **找不到 `TARGETS: FoodJournal`** | 打开的是 `project.pbxproj` 源码（带行号的文本），不是工程设置界面 | 点左侧导航栏**最顶端的蓝色工程图标**，编辑器左栏才会出现 `PROJECT` / `TARGETS`（详见 1.3） |
| 配好的签名 / Team 某次「自己没了」 | 工程是 XcodeGen 生成物，重新生成会覆盖 `project.pbxproj` | 把 `DEVELOPMENT_TEAM` 写进 `project.yml`（详见 1.3 的警告） |
| `Window → Devices and Simulators` 一打开就闪退 | 该入口已变为 Xcode 自带 DeviceHub，当前 beta 存在布局死循环 bug | 本指南流程不需要它；设备管理用 `xcrun devicectl list devices`，脚本见 `tools/ios-devmode.sh` |
| 测试连通报「API Key 无效」 | Key 填错/多余空格/非 Agent Plan Key | 重新粘贴；火山 Agent Plan 的 Key 与普通方舟 Key 是两套 |
| 测试连通报「端点或模型不存在」 | BaseURL 或模型 ID 不符 | 检查 BaseURL 是否 `/api/plan/v3`，模型 ID 是否 `doubao-seed-2.0-mini` |
| 识图超时/失败 | 网络不稳或额度用尽 | 换网络重试；到火山控制台看套餐额度 |
| App 7 天后打不开 | 免费签名过期 | Xcode 重新 Run 覆盖安装（见四） |

## 八、命令行推送（可选，等价于点 Run）

不开 Xcode 也能推版本，且可复现。UDID 用 `tools/ios-devmode.sh status` 查：

> **仓库位置：`~/Developer/FoodJournal`** —— 刻意不放在 `~/Documents` 下。该目录受 macOS TCC 保护，launchd 后台任务读不到，自动推送会以退出码 126 静默失败（`~/Library/Logs/foodjournal-autopush.err.log` 里会看到 `Operation not permitted`）。

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
cd ~/Developer/FoodJournal

xcodebuild -project FoodJournal.xcodeproj -scheme FoodJournal -configuration Debug \
  -destination 'platform=iOS,id=00008130-000651EA2652001C' \
  -derivedDataPath .build/DerivedData -allowProvisioningUpdates \
  OTHER_SWIFT_FLAGS='-Xfrontend -disable-sandbox' build

xcrun devicectl device install app --device 00008130-000651EA2652001C \
  .build/DerivedData/Build/Products/Debug-iphoneos/FoodJournal.app

xcrun devicectl device process launch --device 00008130-000651EA2652001C com.somethingwierd.FoodJournal
```

> ⚠️ **`OTHER_SWIFT_FLAGS='-Xfrontend -disable-sandbox'` 不能省**。在受限进程环境（AI 助手 / 沙箱终端）里跑 xcodebuild 时，Swift 编译器给宏插件（`@Model`、`@State` 等）套的沙箱会套用失败：
> `sandbox-exec: sandbox_apply: Operation not permitted` → `swift-plugin-server produced malformed response` → 一堆「external macro implementation type ... could not be found」假错误。
> 加该开关即绕过（已验证有效）。**在 Xcode 图形界面里点 Run 不会遇到这个问题**，所以日常手动推版本照旧点 Run 即可。
>
> 验证安装结果：`xcrun devicectl device info apps --device <UDID> | grep somethingwierd` 看版本号；安装后想确认没闪退：`xcrun devicectl device info processes --device <UDID> | grep FoodJournal`（有进程 = 活着）。
